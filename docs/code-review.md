# Код-ревью Lines (MonoGame/KNI)

Дата: 2026-10-12. Ветка: `feature/code-review`. База: `main` (`d5a94d2`).

Общая оценка: архитектурный каркас крепкий — логика (`LogicLines`) отделена от UI и
покрыта тестами, shared-проект + тонкие хосты дают кроссплатформенность без `#if`-лапши.
Главные риски: три критичных бага и неатомарная запись JSON-хранилищ.

## 1. Сильные решения

- Разделение логики и UI: `LogicLines.Game` не знает о MonoGame, общается делегатами
  (`ShowItem`/`ShowScore`); логика в net8.0-библиотеке с юнит-тестами.
- Фуззер с инвариантом `free_fields == (map == 0)` после каждого шага, с дампом
  состояния и логом кликов при падении (`tests/LogicLines.Tests/FuzzTests.cs:23-59`).
- Событийная модель анимаций: GameScreen превращает пошаговые события логики в плавный
  визуал (glide/appear/burn).
- Абстракции платформы (`IKeyValueStore`, `INamePrompter`, `ITextSource`) — тонкие;
  Web подменяет хранилище на localStorage через конструктор `LinesGame`.
- `BoardLayout.Compute` — чистая функция без состояния, единая для Update и Draw.
- `FontSet` — корректное решение апскейла SpriteFont (выбор наименьшего достаточного растра).
- Защитная загрузка JSON: битый файл → откат на дефолты во всех сервисах.
- Локализация: английский базовый класс = fallback; русская плюрализация (1/2/5, 11–14)
  корректна (`src/Lines.Shared/Localization/Strings.cs:170-183`).

## 2. Критичные баги

### Б1. Лишний шарик каждый ход после хода на клетку-подсказку
`src/LogicLines/Game.cs:337-358` (`ShowNextBall`). Если игрок ходит на клетку-подсказку
(`map == -1`), при показе следующих шариков `map[next.x,next.y] > 0` и вызывается
`SelectNextBall(next.color)` — но результат присваивается локальной копии структуры
`next` (Game.cs:342), а `balls[i]` продолжает указывать на занятую клетку. На следующем
ходу перенос срабатывает снова → +1 шарик за ход до конца партии.
Исправление: писать результат обратно в `balls[i]`.

### Б2. Крах SpriteFont на неподдерживаемых символах в имени
`src/Lines.Shared/Screens/GameScreen.cs:563-572` (`OnCharTyped`) фильтрует только
`char.IsControl`; шрифт содержит ASCII 32-126 + кириллицу. Эмодзи/иероглифы → исключение
в `DrawNameEntry` (GameScreen.cs:1276-1284). Тот же вектор — нативный диалог Android
через `AskNameNative` (GameScreen.cs:513-528).
Исправление: фильтр по алфавиту шрифта / whitelist (ASCII + кириллица).

### Б3. Нет валидации координат следующих шариков при загрузке сейва
`src/Lines.Shared/Screens/GameScreen.cs:792-798`, `src/LogicLines/Game.cs:100-105`.
Повреждённый `saves.json` с координатой вне поля → `IndexOutOfRangeException` в
`ShowNextBall` на следующем ходу.
Исправление: проверка диапазонов x/y/color, невалидный шарик → `x = -1`.

### Б4. Неатомарная запись JSON-хранилищ
`src/Lines.Shared/Settings/IKeyValueStore.cs:44-56` (`FileKeyValueStore.Write`):
файл усекается перед записью; авария посередине → молчаливый сброс всех
рекордов/сейвов/настроек на дефолты при следующем запуске.
Исправление: запись в `name + ".tmp"` + `File.Move(tmp, path, overwrite: true)` +
`.bak` предыдущей версии как fallback при чтении.

## 3. Логика (Game.cs) — прочие замечания

- Хрупкий бэктрекинг пути (463-479): сосед ищется по `IsPath(…, nr)` до декремента `nr`;
  путь визуально может «прыгать» на клетку с тем же номером волны.
- Скрытый перезапуск: `ClickBox` в статусе `stop` молча переводит в `init` (147-148).
- `CheckLine` проверяет `color == 0` вместо `<= 0` (586-588): пять резерваций подряд
  соберутся в «линию цвета -1».
- `static Random` (202): не потокобезопасен, тесты зависят от порядка → поле экземпляра.
- Мёртвый код порта: `foot`/`rotate` в протоколе `ShowItem` и `JumpBall` (373-382) —
  UI их игнорирует.
- `FieldMap` отдаёт живой массив (69) — нарушение инкапсуляции.
- Стиль: `snake_case` поля, lowercase enum (`Item.empty`) — наследие порта.

## 4. GameScreen — god-object (1386 строк)

В одном классе: маршрутизация ввода с 5 оверлеями (340-462), анимации, save/restore,
game-over-флоу, ввод имени, таблица рекордов, ~200 строк графики пьедесталов (1033-1140).

- Декомпозиция: `BoardRenderer` (поле + шарики + следы + анимации), `PedestalRenderer`,
  `OverlayDialogs` (каркас диалога повторяется трижды: 1225-1261), `GameOverFlow`.
- Эвристики распознавания событий логики (619-655): «81 empty = сброс», «≥2 jump =
  сжигание» — любое изменение протокола LogicLines молча сломает анимации. Нужны
  типизированные события (`ResetField`, `BurnStart(cells)`, `MoveStep(from,to)`).
- Магические индексы кнопок 0..5 (432-440), синхронизированы вручную с `btnNames`
  (249-250) → `enum PanelButton`.
- `pendingClick` обходит проверки оверлеев (321-326): клик по полю пройдёт даже при
  открытом диалоге выхода.
- Неограниченный catch-up шагов логики (311-318): после паузы окна прогонит сотни
  `Step()` за кадр → ограничить ~4 шагами.
- Мутация состояния в Draw (873, 911) — при пропущенном Draw анимация замирает.
- `ShowTrails` — публичное изменяемое поле (65), пишется каждый кадр; читать настройки
  напрямую.
- Константа `IconButtonCount` объявлена в середине класса (995), используется с 41.
- Магические числа отрисовки (`0.92f` дважды: 919, 1381; палитра литералами) → `UiTheme`.

## 5. Hot path: аллокации и лишняя работа

- `SavesScreen` вызывает `CaptureSave()` каждый кадр (SavesScreen.cs:141) ради булева
  флага — копирование 90 значений × 60 fps → заменить на `Func<bool>`.
- `RelativeTime.Format` в Draw (GameScreen.cs:1323): `TryParseExact` + форматирование
  на строку таблицы на кадр → кэшировать при открытии таблицы.
- Строки счёта/очков каждый кадр (949, 1318-1320) → кэш с инвалидацией в `OnScore`.
- `new List<int>()` на каждый шаг логики (660) → переиспользуемый буфер.
- `new Rectangle[10]` в layout на кадр (SavesScreen.cs:166).
- Ресурсы без Dispose: `pixel` в четырёх экранах, тень BallRenderer (35); SplashScreen
  пересоздаётся при каждом `ShowSplash()` → `IDisposable` или общий `Primitives`.

## 6. Хранилище и сервисы

- Нет версионирования форматов (`GameSettings`, `GameSave`, `ResultEntry`) → добавить
  `int Version = 1`.
- Даты — локализованные строки `"dd.MM.yy HH:mm"` (ResultEntry.cs:9-10, GameSave.cs:12):
  несортируемы, неоднозначны → ISO 8601 + форматирование в UI.
- Полное глотание ошибок записи (IKeyValueStore.cs:37-40, 52-55): переполнение
  localStorage, отказ в правах — всё тихо → событие `WriteFailed` + индикация в UI.
- Потокобезопасность не задокументирована: callback `Activity1.PromptName` приходит с
  UI-потока Android (Activity1.cs:63,75-76) и тянет `settings.Update` → возможна гонка
  с игровым потоком → маршаллировать в игровой поток / `lock` в сервисах.
- `ResultsService.Add` находит индекс по паре (имя, счёт) (86-87) — при совпадении
  подсветится чужая запись.
- `SavesService.Load` молча обрезает лишние слоты (53-54).
- `ResultsService.Load` не дедуплицирует имена из легаси-файлов (38-41).

## 7. Локализация

- Наследование приемлемо для ru/en, плохо масштабируется дальше: третий язык = ~70
  override копипастой, непереведённое молча падает в английский.
- Строки захардкожены в коде → правка текста = пересборка.
- `Strings.Current` — глобальный static, мешает тестам; `Resolve`/`Plural` — чистые
  функции, тестируются за 10 минут, но тестов нет.

## 8. Хосты и инфраструктура

- `.projitems`: каждый новый файл добавляется вручную; shared-код не собирается и не
  тестируется отдельно → `Settings/*` и `Strings` без тестов. Обычная class library
  net8.0 сняла бы обе проблемы.
- Концентрация `#if ANDROID || BLAZORGL` / `OperatingSystem.Is*` в shared-коде растёт →
  интерфейс `IPlatformServices` (окупится на iOS).
- `JsNamePrompter` (JsNamePrompter.cs:25): блокирующий `prompt()`, подавляется
  браузерами → HTML-оверлей в Blazor.
- `PointerInput.Reset()` при программной смене экрана — теоретический фантомный клик.
- Тесты: только LogicLines; seed фуззера недетерминирован (`Environment.TickCount`) →
  фиксированный набор seeds + seed из env-var.
